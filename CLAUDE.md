# Osiris OS - Project Context

## Overview

Osiris is a Linux distribution: Arch underneath, a Cinnamon desktop that is
themed properly, and a graphical installer on a live ISO. It was rebuilt
ground-up after v1 (Debian + live-build, dual Sway/Cinnamon) was scrapped as
too painful to build and too bloated.

The scope is deliberately narrow. Osiris writes no GTK theme, no icon set and
no compositor; it orchestrates the ones that exist. What it adds is coherence -
one theme choice retints nine surfaces at once - and an install that produces
that rather than a base system you then configure by hand.

The full design is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Read it before making non-trivial decisions.

The build order and priorities are in [docs/ROADMAP.md](docs/ROADMAP.md). Refer to it before starting new work.

The project's language - Theme, Skin, Harness, Engine, Program and the rest - is
defined in [CONTEXT.md](CONTEXT.md). Use those terms as defined there.

[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) has the iteration loop, the bash
accounting, and a list of traps that have each cost a day. Read it before
writing code that touches a user's home directory, a disk, or a GTK widget.

## Stack at a glance

- **Base**: Arch Linux
- **Desktop**: Cinnamon (Muffin, X11) with Plank as the dock and rofi as the launcher
- **Login**: LightDM + lightdm-slick-greeter, branded
- **Terminal**: ghostty (the only candidate that renders font ligatures; VTE terminals cannot)
- **User shell**: zsh with oh-my-zsh
- **Theming**: manifests in `shell/themes/`, compiled into a real GTK theme per palette. See [docs/THEMING.md](docs/THEMING.md).
- **Appearance app**: GTK4 + libadwaita in Python (`apps/appearance/`), picker and theme creator
- **Installer**: GTK4 + libadwaita in Python (`apps/installer/`), on a live ISO built with archiso (`iso/profile.py`)

Hyprland, AGS and greetd were removed. The desktop is Cinnamon; do not propose
reinstating them without being asked.

## Hard rules

### No bash that we author

The v1 pain point was bash chroot hooks inside a 30-60 minute Docker build with no stack traces. This repository contains zero `.sh` files we wrote. Build, install, hooks and glue are Python, and every process is spawned as an argv array (`subprocess.run(["pacman", ...])`), never `bash -c`.

bash exists on the system as an Arch dependency and is the user's interactive shell. The rule is about what we author, not what's installed.

Current state: zero `.sh` files, zero `shell=True`, zero `bash -c`. The one bash
file archiso requires is generated by `iso/profile.py`, and `/etc/skel/.zshrc`
is user shell configuration. See docs/DEVELOPMENT.md for the full accounting.

### No emojis

Project-wide: no emojis in code, configs, docs, commit messages, or PR descriptions. Keep tone professional and technical.

### Research before implementation

Do not guess technical details. Use WebSearch for documentation, syntax, supported features. Verify assumptions before writing code. Examples: "does this config file support tilde expansion," "what is the exact pacman syntax for X," "what tool flag does Y."

### Orchestrate, do not implement

Osiris ships no GTK theme, no icon set and no desktop component of its own.
Each would be a permanent maintenance cost against a moving upstream, and the
packaged options are good. When a feature seems to need one of those, the
answer is almost always to configure or generate against what upstream already
ships. See docs/THEMING.md.

### Never hand-roll critical system machinery

Installing the OS, partitioning disks, setting up the bootloader, detecting
drivers, building the ISO, delivering updates: these are done by the tools Arch
already maintains (archinstall, archiso's releng profile, pacman packages), not
by code we write. Osiris owns the screens, the desktop, the themes and the
branding. It does not own anything that can leave a machine unbootable or a
disk erased. If a feature seems to need us to write that kind of code, stop and
find the maintained tool first. See docs/adr/0012.

## Development workflow

See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md). In short: work against the
`osiris-dev` libvirt VM, which has this repo shared in over virtiofs; build the
ISO with `python3 iso/profile.py` as root.

Two rules worth repeating here because they are silent when broken:

- Write into a user's home through `provision/homes.py`, never with bare
  `os.makedirs` + `os.chown`.
- Resolve the running user's home with `shell/themes/paths.py:home()`, never
  with `os.path.expanduser("~")`.

## What this project is not

- Not a Debian or Ubuntu derivative. Arch only.
- Not a multi-DE distro. Cinnamon only.
- Not a general-purpose distro. Opinionated, and small on purpose.
- Not built with bash, live-build, Docker chroot hooks, or Calamares. None of that.
- Not built with mkosi either: it has no ISO output format. archiso, with the
  profile generated from Python. See docs/ARCHITECTURE.md.
